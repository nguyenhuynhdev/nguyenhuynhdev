# generateStaticParams Guide for Dashboard

## How It Works

### ✅ Already Working: Locale Parameter
The parent `[locale]/layout.tsx` has `generateStaticParams()` which handles locale for **ALL** child routes:

```typescript
// src/app/[locale]/layout.tsx
export async function generateStaticParams() {
  return i18n.locales.map((locale) => ({ locale: locale }));
}
```

This means all routes under `[locale]` automatically get locale params generated:
- `/vi/dashboard` ✅
- `/en/dashboard` ✅
- `/vi/dashboard/blogs` ✅
- `/en/dashboard/blogs` ✅

### ❌ Cannot Use: Client Components
Client components (`'use client'`) **cannot** export `generateStaticParams()` because it's a server-side function.

All dashboard pages are client components because they use:
- React hooks (`useState`, `useEffect`, `useRouter`)
- Client-side authentication
- Interactive UI

### ✅ Solution: dynamicParams Export

For dynamic routes like `[id]`, use `export const dynamicParams = true` to allow runtime params:

```typescript
// src/app/[locale]/dashboard/blogs/[id]/edit/page.tsx
'use client';

export const dynamicParams = true; // Allow params not generated at build time

// ... rest of component
```

This tells Next.js: "If a param isn't pre-generated, handle it at runtime (client-side)."

## Adding dynamicParams to Dynamic Routes

If you have other dynamic routes, add this:

```typescript
'use client';

export const dynamicParams = true; // Add this line

// ... rest of imports and component
```

## Why This Works for Static Export

1. **Locale params** are pre-generated by parent layout
2. **Dynamic IDs** are handled client-side (perfect for authenticated routes)
3. **Static export** works because the locale structure is known at build time
4. **Client-side routing** handles the actual blog/project IDs

## Alternative: Server Component Wrapper (Not Recommended for Dashboard)

If you absolutely need to pre-generate all blog IDs, you'd need server component wrappers:

```typescript
// page.tsx (Server Component - wrapper)
import { i18n } from "@/i18n/i18n-config";
import ClientPage from "./client-page";

export async function generateStaticParams() {
  // Would need access to database at build time
  const blogs = await getAllBlogIds(); // This won't work with static export
  return blogs.map(blog => ({ locale: 'en', id: blog.id }));
}

export default function Page({ params }) {
  return <ClientPage params={params} />;
}
```

**This is NOT recommended** for dashboard because:
- Requires database access at build time
- Not compatible with static export + Cloudflare Pages
- Blog IDs change dynamically based on user content
